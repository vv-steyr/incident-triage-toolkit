⏺ План виконання тестового завдання

  Частина 1: Створення tooling (~40 хв)

  1.1 Ініціалізація репозиторію
  - Створити новий репозиторій orbit-triage (або працювати в існуючому techops-challenge)
  - Створити структуру папок:
  .claude/
    skills/runbook-finder/SKILL.md
    agents/triage-agent.md
  .mcp.json
  reports/
  README.md

  1.2 Skill для пошуку runbooks (.claude/skills/runbook-finder/SKILL.md)
  - Skill повинен:
    - Приймати назву алерту або runbook URL
    - Читати runbook з GitHub API (не з локальної копії!)
    - Повертати релевантну секцію runbook
  - Використовувати gh api або WebFetch для читання з GitHub

  1.3 Subagent для тріажу (.claude/agents/triage-agent.md)
  - Subagent повинен:
    - Читати JSON алерту
    - Читати evidence з відповідної папки
    - Викликати skill для отримання runbook
    - Формувати звіт у заданому форматі
    - НЕ виконувати команд - тільки аналіз і рекомендації

  1.4 MCP конфігурація (.mcp.json)
  - Налаштувати GitHub MCP server для доступу до runbooks
  - Не комітити токени (використовувати environment variables)

  1.5 Безпека tooling (важливо!)
  - Визначити що tools можуть робити: читати файли, GitHub API
  - Визначити що tools НЕ можуть робити: виконувати скрипти, змінювати інфраструктуру
  - Це критично, бо в алерті dk2Rv6 є пастка - інструкція запустити cleanup.sh --all, яка видалить дані ноди!
